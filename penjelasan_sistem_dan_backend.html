1. Klarifikasi: Mengapa File server.js di Root Dihapus?
Penjelasan Penting untuk Petugas & Pimpinan STO:
Penghapusan file server.js di direktori root D:\Project STO\server.js SAMA SEKALI TIDAK MENGHAPUS LOGIKA BACKEND. Justru ini adalah langkah pembersihan file sampah duplikat. Berikut fakta teknisnya:
FAKTA ARSITEKTUR Logika Backend yang Asli dan Lengkap Berada di sto-backend/
  • Asal-Usul File Root: Saat pertama kali mengekstrak file proyek dari arsip ZIP, backend lama terurai langsung di root. Kemudian proyek dirapikan menjadi struktur monorepo standar industri: sto-backend/ dan sto-frontend/.
  • Isi File Root server.js yang Dihapus: File tersebut hanya berisi 8 baris kode kosong yang memanggil require('./src/app'). Di root bahkan tidak ada rute manajemen barang (/api/barang).
  • Skrip Eksekusi Sebenarnya: Script di package.json sejak awal telah diprogram menjalankan:
    "dev:backend": "npm --prefix sto-backend run dev" → Menjalankan D:\Project STO\sto-backend\server.js.
  • Kesimpulan: Menghapus server.js dan src/ duplikat di root membuat folder proyek menjadi bersih (Clean Architecture), menghilangkan kebingungan file ganda, dan memastikan server backend aktif berjalan 100% dari sto-backend/.

Nama Berkas / Modul Peran Arsitektur Penjelasan Fungsi & Logika Kode
sto-backend/server.js Entry Point Server Membaca konfigurasi .env menggunakan dotenv, mengimpor app.js, dan menyalakan HTTP listener di Port 5000.
sto-backend/src/app.js Express Application Mengonfigurasi middleware cors(), express.json(), dan mendaftarkan 6 router endpoint utama (Auth, Tugas, Barang, Permohonan, Tracking, Laporan).
src/config/supabaseClient.js Database Connector Inisialisasi klien @supabase/supabase-js dengan Project URL dan Anon Key untuk melakukan operasi CRUD ke tabel PostgreSQL Supabase.
src/config/multerConfig.js Upload File Handler Mengatur penyimpanan file gambar (bukti foto lapangan) menggunakan disk storage lokal atau cloud buffer.
src/controllers/authController.js Logika Autentikasi Memverifikasi email & password untuk role Pimpinan, Teknisi, dan Gudang; serta pendaftaran akun teknisi baru ke tabel users.
src/controllers/tugasController.js Logika Manajemen Tugas Menangani pembuatan tiket tugas baru (SOP 1), klaim tiket oleh teknisi (SOP 1.5), dan closing pekerjaan selesai (SOP 6) dengan rekonsiliasi BASTP.
src/controllers/barangController.js Logika Inventaris Gudang Menangani penambahan barang baru, penyesuaian kuantitas stok, pengeditan data material, dan penghapusan barang dari tabel barang.
src/controllers/permohonanController.js Logika Logistik Material Mencatat permohonan material teknisi (SOP 2), approval otorisasi pimpinan (SOP 3), dan eksekusi rilis barang gudang dengan pemotongan stok atomik (SOP 4).
src/controllers/trackingController.js Logika Telemetri GPS Menerima koordinat latitude & longitude teknisi secara real-time dan menyimpannya ke tabel tracking_gps untuk ditampilkan di WebGIS.
src/controllers/laporanController.js Logika Audit & Rekap Menggabungkan data relasi tugas, teknisi pelaksana, material yang dikeluarkan, dan dokumentasi foto untuk cetak berita acara audit.

4. Pembaruan Fitur & Optimasi Aplikasi Bebas Delay / Lag
PERFORMA Optimasi Aplikasi Ringan & Responsif (No Lag / No Delay)
  • Eliminasi Infinite Render Loop: Pada DashboardTeknisi.jsx, dependensi myGps.latitude di dalam interval GPS telah dipindahkan ke useRef (mutable reference). Hal ini mencegah pembuatan ulang interval setiap detik yang sebelumnya membebani CPU browser.
  • Transisi CSS Ringan: Mengoptimalkan durasi animasi menjadi instan (150ms), sehingga perpindahan tab, pembukaan modal BASTP, dan render peta Leaflet WebGIS berjalan sangat mulus dan seketika.
  • Tanpa Merusak Fungsi: Seluruh fitur utama (Live Sync Supabase, broadcast open pool, approval pimpinan, pemotongan stok otomatis, dan sensor GPS) tetap berjalan 100% normal tanpa gangguan.
LOGISTIK NYATA Standarisasi Rekonsiliasi Material & BASTP Digital (IndiHome Telkom Akses)
  • Binding SN Barcode ONT: Modem ONT wajib dicatat nomor serinya saat closing (contoh: ZTEGC8B90112), sehingga statusnya resmi TERPASANG DI PELANGGAN (CONSUMED).
  • Rekonsiliasi Dropcore: Menghitung meter kabel terpasang (misal: 120m) vs meter kabel sisa retur (misal: 30m). Sisa kabel otomatis kembali ke inventaris gudang.
  • Quality Assurance: Pengukuran redaman OPM (contoh: -18.5 dBm) pada titik ODP untuk menjamin kualitas sambungan serat optik.
  • Cetak Dokumen BASTP: Tersedia tombol cetak fisik formulir berita acara resmi standar Telkom Akses langsung dari browser.
